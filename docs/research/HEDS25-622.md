# HEDS25-622 — Diagnostic des données gamification

Date : 22 septembre 2026  
Environnement observé : `test.hedsvs.ch` uniquement  
Production : non consultée et non modifiée

## Objectif validé

Le ticket reprend GAM-010 de la feuille de route validée : identifier puis
traiter, sans suppression définitive, les données gamification orphelines,
expirées ou incohérentes avant la suite du pilote.

## Diagnostic agrégé en lecture seule

Le contrôle a été exécuté dans une transaction PostgreSQL `READ ONLY`. Aucun
identifiant utilisateur ni aucune donnée nominative n'a été exporté.

| Contrôle | Résultat |
| --- | ---: |
| Profils gamification sans `user_profiles`/Auth | 3 |
| Progressions de quête sans profil | 25 lignes / 14 anciens utilisateurs |
| Profils dont la maison est uniquement dans `gamification_data` | 193 |
| Profil sans maison | 1 compte admin |
| Maisons invalides | 0 |
| Doubles badges | 0 |
| Badges/défis actifs incompatibles | 0 |
| Étapes de quête inconnues | 0 |
| Écarts entre solde XP et journal | 0 |
| Niveaux ou points maison incohérents | 0 |
| Agrégats de maisons incohérents | 0 |
| Contenus actifs expirés | 0 |

Deux quêtes historiques terminées n'ont pas d'étapes. Elles sont conservées
explicitement comme historique : elles ne sont ni actives ni bloquantes.

## Cause principale

`gamification_data` est la source utilisée par les écrans gamification, tandis
que `user_profiles.house_id` n'a pas été synchronisé lors des anciennes
attributions. De plus, `gamification_data` et `user_quest_progress` ne possèdent
pas de contrainte de rattachement à `user_profiles`, ce qui a conservé des
lignes après la disparition d'anciens profils.

## Décision

- Conserver les historiques orphelins dans les tables publiques mais les
  enregistrer dans une quarantaine privée, inaccessible à l'API publique.
- Synchroniser `user_profiles.house_id` depuis la source gamification
  canonique et auditer chaque correction.
- Faire écrire les attributions futures dans les deux représentations au sein
  de la même transaction.
- Refuser toute nouvelle donnée gamification rattachée à un utilisateur qui
  n'a pas de profil applicatif.
- Fournir une prévisualisation agrégée distincte de l'application, idempotente
  et réservée aux administrateurs.
