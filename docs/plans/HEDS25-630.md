# Objectif

Calculer la charge SI par enseignant canonique, sans doublon causé par la casse, les accents, les points, les tirets ou les variantes historiques de noms.

# Règles métier retenues

- L’identité Supabase (`user_id`) est prioritaire lorsqu’elle est présente dans un créneau.
- L’email normalisé est le second identifiant stable.
- Le nom normalisé est uniquement un mécanisme de compatibilité pour les anciennes données.
- Une identité ambiguë ou inconnue est signalée dans le diagnostic; elle n’est jamais fusionnée arbitrairement.

# Périmètre validé

- [x] Auditer les identités présentes dans les créneaux de la base test.
- [x] Introduire un résolveur déterministe vers les enseignants SI canoniques.
- [x] Dédupliquer un même enseignant présent sous plusieurs représentations dans un créneau.
- [x] Exposer les identités non résolues et ambiguës dans le diagnostic de charge.
- [x] Conserver la compatibilité avec les anciens noms et alias connus.
- [x] Ajouter les tests métier ciblés.
- [x] Vérifier le lint et le build.
- [x] Déployer et vérifier uniquement sur `test.hedsvs.ch`.

# Hors périmètre

- Aucune réécriture destructive des créneaux existants.
- Aucun changement de données ou déploiement en production.
- Aucune fusion automatique de comptes Supabase.
