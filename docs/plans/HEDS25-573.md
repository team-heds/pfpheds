# Plan d'implémentation

1. Centraliser les contrats Supabase critiques étudiants/dashboard/PFP dans un module sans effet de bord et remplacer uniquement les sélections concernées.
2. Rendre `pfpStatsService` déterministe avec une fabrique unique de statistiques, une lecture robuste des capacités PFP1A/PFP1B et des tests de régression.
3. Ajouter `npm run doctor` pour contrôler les fichiers et clés d'environnement attendus, les ports frontend/backend, les healthchecks backend/Supabase et les contrats de colonnes en lecture seule, sans jamais afficher les secrets.
4. Instrumenter les navigations Vue Router avec des noms de routes et un historique borné, puis supprimer seulement les chargements dupliqués démontrés par les tests.
5. Ajouter et exécuter les tests ciblés étudiants, dashboard et PFP, le contrôle de format du diff et le build de production.

# Limites explicites

- Pas de migration, de write SQL, de modification RLS/auth ou de suppression de fonctionnalité.
- Pas de refonte UI dans ce lot.
- Pas de merge ni de déploiement automatique; livraison par PR vers `prod` après validation.

# Retour arrière

- La branche est isolée. Chaque lot est commité séparément si possible et peut être revert sans toucher au schéma ni aux données.
