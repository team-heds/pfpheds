# HEDS25-597 — Besoins de places de stage

## Parcours confirmé

- Route : `src/router/routes/pfp.js` → `PlacesViewPHYFP.vue`.
- Données de capacité : store `places`, champs JSON `PFP1A`, `PFP1B`, `PFP2`, `PFP3`, `PFP4`, avec clés `2027` ou `2026-2027`.
- Critères : drapeaux `MSQ`, `SYSINT`, `NEUROGER`, `AIGU`, `REHAB`, `AMBU` sur chaque place.
- Étudiants et validations : `studentsService`, `StudentsPhysio.pfp_valided/pfp2_data`, puis `student_result_vote`.
- Référence existante : `ManagementOffreView.vue` calcule déjà les étudiants restant à placer par PFP et année.

## Décision

Ajouter un composant de lecture seul sous le tableau. Le calcul reste côté client et réutilise les politiques RLS de la page : aucune nouvelle table, migration, fonction privilégiée ou écriture Supabase.

Les besoins par critère sont une estimation : un étudiant est compté s’il n’a pas encore validé de stage portant le critère. Une même place peut porter plusieurs critères, donc les lignes ne sont jamais additionnées pour construire le total des places.

## Risques couverts

- variantes de clés d’année ;
- capacités vides, négatives ou non numériques ;
- étudiants hors classe cible ;
- critères multiples sur une même place ;
- absence de besoin ou d’offre ;
- affichage responsive et état d’erreur explicite.
