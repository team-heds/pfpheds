# Plan — Contrat unique des agrégats du dashboard admin

## Objectif

Créer un endpoint serveur versionné qui fournit des agrégats admin fiables, autorisés et explicitement typés, sans modifier encore l'interface du dashboard. Ce ticket pose le socle utilisé ensuite par HEDS25-592 à HEDS25-596.

## Périmètre autorisé

- Nouveau module serveur dédié aux statistiques du dashboard.
- Montage de la route dans le backend Express existant avec authentification JWT Supabase et permissions explicites.
- Définitions et validateurs partagés du contrat de réponse.
- Tests backend de calcul, erreurs, autorisations et absence de données personnelles inutiles.
- Documentation des définitions métier et des limites connues.

## Hors périmètre

- Refonte visuelle ou responsive du dashboard.
- Branchement des sélecteurs de périodes et filtres dans le frontend.
- Suppression immédiate des anciens services frontend.
- Migration destructive, modification de données de production ou changement RLS.
- Ajout d'une clé `service_role` au frontend.

## Tâches ordonnées

- [x] **1. Formaliser le contrat v1 et les définitions de KPI**
  - Objectif : définir les champs communs (`value`, `status`, `source`, `asOf`, `period`, `error`) et les quatre domaines général, PFP, académique et gamification.
  - Fichiers attendus : `backend/dashboard/adminDashboardContract.js`, `docs/contracts/admin-dashboard-v1.md`.
  - Autorisé : schéma JSON/validateurs légers et définitions exactes à partir du schéma Supabase de référence.
  - Interdit : valeur aléatoire, constante présentée comme une donnée réelle, récupération de données sans usage documenté.
  - Tests : validation d'une réponse complète, rejet d'un domaine/champ invalide, distinction `ok`/`unavailable`/`error`.
  - Validation : `npm --prefix backend test`.
  - Sécurité : le contrat ne contient ni email, ni nom, ni identifiant individuel.

## Risques et décisions requises

- **Définition de “places disponibles” et “PFP en cours”** : si les colonnes actuelles ne permettent pas un calcul certain, le contrat retournera `unavailable` avec une raison ; aucune estimation ne sera conservée.
- **Périodes** : le contrat réserve les métadonnées de période, mais les calculs historiques sont implémentés dans HEDS25-592.
- **Supabase** : aucune migration ni modification RLS n'est prévue pour cette première livraison. Si une migration devient nécessaire, elle fera l'objet d'un plan et d'une migration append-only séparés.
- **Déploiement** : l'endpoint est rétrocompatible et non consommé par l'interface avant HEDS25-593, ce qui réduit fortement le risque production.
