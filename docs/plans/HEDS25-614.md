# HEDS25-614 — Politique de reprise historique de la gamification

## Objectif

Permettre à un administrateur de simuler puis d'appliquer une reprise de badges
historiques sans distribuer d'XP, sans exposer de données personnelles dans les
rapports techniques et sans créer de doublon lors d'une relance.

## Décisions validées

- Les badges présents avant cette politique sont classés
  `legacy_unclassified` : ils restent visibles mais ne sont jamais récompensés
  rétroactivement.
- Une nouvelle reprise explicite crée des badges avec l'origine
  `historical_import` et un identifiant de lot.
- Une règle inconnue, invalide ou non prise en charge est mise en quarantaine et
  n'entraîne aucune attribution.
- L'aperçu et le rapport enregistré sont uniquement agrégés ; ils ne contiennent
  ni nom, ni adresse e-mail.
- Seul un administrateur reconnu par `app_is_privileged()` peut prévisualiser ou
  appliquer une reprise.
- Aucun changement de production n'est inclus dans ce ticket.

## Plan d'implémentation

- [x] Ajouter la provenance et le lot de reprise aux badges utilisateurs sans
  supprimer ni réécrire leur contenu métier.
- [x] Ajouter un registre privé et immuable des lots appliqués.
- [x] Centraliser l'évaluation des candidats dans une fonction privée partagée
  entre l'aperçu et l'application.
- [x] Exposer deux RPC administratives sécurisées : simulation agrégée et
  application idempotente sans XP.
- [x] Ajouter les tests SQL d'autorisation, de quarantaine, de provenance,
  d'absence d'XP et de rejeu.
- [x] Vérifier puis appliquer uniquement sur la base de test après sauvegarde.

## Critères d'acceptation

1. L'aperçu ne produit aucune écriture et ne retourne aucun identifiant
   utilisateur, nom ou e-mail.
2. Un lot appliqué deux fois crée les mêmes résultats sans doublon.
3. Les lignes importées portent `historical_import`, le lot et la version de
   règle, sans entrée `BADGE_UNLOCK` dans `xp_history`.
4. Une règle ambiguë est comptée comme `quarantined` et n'est pas insérée.
5. Un étudiant ou un appel anonyme ne peut ni simuler ni appliquer une reprise.
6. Les badges préexistants sont conservés et classés
   `legacy_unclassified`.

## Retour arrière

La migration est additive. En cas d'anomalie sur test, révoquer l'exécution des
RPC publiques puis restaurer leur version dans une migration compensatoire. Les
lots et provenances restent conservés pour l'audit ; aucune suppression
automatique n'est autorisée.
