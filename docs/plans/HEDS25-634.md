# HEDS25-634 — Optimiser les requêtes et agrégations SI

## Objectif

Réduire les lectures répétées de `planning_time_slots` dans les dashboards Soins infirmiers, sans modifier les données métier, les droits ni le schéma Supabase.

## Périmètre livré

- charger un seul instantané paginé du planning de l'année académique active par dashboard ;
- partager cet instantané entre les indicateurs, le planning hebdomadaire, les séances à venir, la charge, les postulations et le contrôle qualité ;
- dédupliquer les chargements simultanés avec un cache court de 60 secondes ;
- conserver un rafraîchissement forcé sur le dashboard RM ;
- paginer explicitement les lectures de secours au-delà de la limite Supabase de 1 000 lignes ;
- calculer les conflits par groupes semaine/jour au lieu de comparer tous les créneaux entre eux ;
- recalculer localement les vues RM après une assignation réussie.

## Hors périmètre

- aucune migration de schéma ;
- aucune correction de données ;
- aucun changement de rôle ou de permission ;
- aucun déploiement en production ;
- aucune transition Jira avant validation humaine.

## Validation attendue sur test

1. Les dashboards Secrétariat SI, Enseignant SI et RM Soins s'ouvrent sans erreur.
2. Chaque chargement utilise un seul parcours paginé de `planning_time_slots` pour l'année active.
3. Les totaux, séances, conflits, postulations et diagnostics restent cohérents.
4. Le changement de semaine RM n'effectue pas une nouvelle lecture du planning.
5. Le rafraîchissement explicite recharge bien l'instantané.
6. L'assignation d'une postulation actualise immédiatement les cours et diagnostics locaux.
