# Plan — Remplacer les dépendances frontend vulnérables

## Objectif

Obtenir un `npm audit --omit=dev` sans vulnérabilité pertinente tout en conservant les parcours d'export Excel et d'édition riche existants.

## Limites

- Autorisé : `package.json`, `package-lock.json`, `vite.config.js`, `TextAreaComponent.vue`, tests frontend ciblés et documentation de ce ticket.
- Interdit : backend, Supabase, migrations, RLS, contrats API, refonte visuelle du social, réécriture générale des exports.
- Une incompatibilité non résolue stoppe la tâche ; elle ne sera pas masquée par une exception d'audit.

## Tâches

### 1. Corriger l'arbre de dépendances

- **Objectif :** supprimer les versions vulnérables sans changer les API métier.
- **Fichiers :** `package.json`, `package-lock.json`, `vite.config.js`.
- **Changements :**
  - épingler SheetJS 0.20.3 depuis la distribution officielle ;
  - forcer la dépendance transitive d'ExcelJS à `uuid@11.1.1` et vérifier la résolution du lockfile ;
  - retirer `quill` et son chunk Vite ;
  - conserver les chunks SheetJS et ExcelJS.
- **Contrôles :** `npm ls xlsx quill exceljs uuid`, `npm audit --omit=dev`.
- **Sécurité :** conserver les seuils d'audit existants et l'intégrité du lockfile.

### 2. Migrer l'éditeur social vers Tiptap

- **Objectif :** remplacer l'unique usage Quill en conservant le contrat public du composant.
- **Fichiers :** `src/components/social/library/TextAreaComponent.vue` et, uniquement si nécessaire, un petit composant/utilitaire d'éditeur partagé existant.
- **Comportements à préserver :** `v-model` HTML, événements `input`/`tag`, limite de caractères, compteur, contenu initial, désactivation et navigation clavier.
- **Tests :** ajouter `tests/unit/textAreaComponent.spec.js` couvrant valeur initiale, saisie/émission, limite et actions de barre d'outils.
- **Accessibilité :** boutons natifs nommés, focus visible, état désactivé et toolbar utilisable au clavier.

### 3. Couvrir les exports représentatifs

- **Objectif :** détecter une incompatibilité SheetJS ou ExcelJS avant la production.
- **Fichiers :** tests unitaires ciblés dans `tests/unit/`; code de production uniquement si un défaut réel est identifié.
- **Tests :**
  - conserver et exécuter `tests/unit/validationPFP.spec.js` pour SheetJS ;
  - ajouter ou compléter un test d'export ExcelJS représentatif qui construit puis sérialise un classeur avec le paquet réellement résolu ;
  - vérifier que les imports dynamiques Vite restent valides.
- **Limite :** ne pas réécrire chaque vue d'export dans ce ticket.

### 4. Exécuter les gates et documenter le résultat

- **Commandes :**
  - `npm audit --omit=dev`
  - `npm run test:security`
  - tests Vitest ciblés du ticket
  - `npm run build:all`
- **Acceptation :** audit pertinent à zéro, tests ciblés verts, build frontend/backend vert et aucun nouveau contournement CI.
- **Traçabilité :** cocher les tâches réalisées, consigner les versions finales et joindre les résultats à la PR/Jira.

## Retour arrière

Restaurer ensemble `package.json`, `package-lock.json`, `vite.config.js` et `TextAreaComponent.vue`. Ne jamais restaurer uniquement le lockfile ou uniquement le composant, car les versions et l'implémentation de l'éditeur doivent rester cohérentes.
