# Recherche — HEDS25-571

## Ticket

- **Objet :** remplacer les dépendances frontend vulnérables.
- **Critères Jira :** aucun avis pertinent dans `npm audit --omit=dev`, traitement documenté de SheetJS, Quill et ExcelJS/UUID, vérification des parcours d'export/import et d'édition riche, build et CI verts.
- **Périmètre :** frontend Vue uniquement. Aucun changement de schéma, de RLS, de route backend ou de contrat API n'est requis.

## État vérifié

L'audit de production remonte quatre vulnérabilités :

| Dépendance | Version actuelle | Sévérité | Cause |
|---|---:|---:|---|
| `xlsx` | 0.18.5 directe | haute | prototype pollution et ReDoS ; le registre npm ne propose pas la version corrigée |
| `quill` | 1.3.7 directe | modérée | XSS ; le correctif npm implique Quill 2 |
| `exceljs` | 4.4.0 directe | modérée | embarque `uuid@8.3.2` |
| `uuid` | 8.3.2 transitive | modérée | génération insuffisamment sûre dans certaines conditions |

Les dépendances sont déclarées dans `package.json`. Le workflow `.github/workflows/deploy-prod.yml` exécute déjà les audits frontend et backend, les tests de sécurité et le build complet : il ne faut ni réduire leur niveau ni ajouter d'exception silencieuse.

## Cartographie d'impact

### SheetJS (`xlsx`)

L'API SheetJS est appelée dans 14 fichiers frontend pour générer des exports, notamment :

- `src/views/admin/pfp/ValidationPFP.vue`
- `src/views/admin/pfp/PlacesAssignedView.vue`
- `src/views/admin/users/TeacherListView.vue`
- `src/service/academicPlanningService.js`
- `src/composables/useModulePlanning.js`
- plusieurs vues de formation pratique et dashboards administratifs.

Le test `tests/unit/validationPFP.spec.js` couvre déjà un export représentatif avec un mock de l'API `xlsx`. La distribution officielle SheetJS 0.20.3 conserve cette surface (`utils`, `writeFile`) et constitue donc le remplacement le moins risqué. La documentation officielle indique que la version 0.18.5 du registre npm est ancienne et publie 0.20.3 via son CDN : https://docs.sheetjs.com/docs/getting-started/installation/frameworks/

### Quill

La seule utilisation applicative passe par `src/components/social/library/TextAreaComponent.vue`, via `primevue/editor`. Le composant est consommé par les écrans de création de publication et de communauté. Il expose actuellement :

- un `v-model` HTML ;
- une limite de 1 000 caractères ;
- les événements `input` et `tag` ;
- un compteur de caractères.

Le projet contient déjà Tiptap (`@tiptap/vue-3` et `@tiptap/starter-kit`) et un exemple fonctionnel dans `src/components/editor/notes/TiptapSimpleEditor.vue`. Remplacer l'implémentation interne de `TextAreaComponent` par Tiptap permet de supprimer Quill sans introduire un second éditeur. Une simple montée vers Quill 2 est risquée car son API clipboard a changé : https://v2.quilljs.com/docs/upgrading-to-2-0

### ExcelJS / UUID

ExcelJS est utilisé dans 12 fichiers pour des exports Excel avancés (styles, dimensions, feuilles), notamment :

- `src/views/admin/users/TeachersSIView.vue`
- `src/views/admin/TeacherAssignmentView.vue`
- `src/views/admin/planning/WeeklyPlanningAdminView.vue`
- `src/views/admin/planning/AnnualPlanningView.vue`
- `src/service/academicPlanningService.js`

`exceljs@4.4.0` dépend de `uuid@^8.3.0`. Le projet utilise déjà `uuid@^11.1.1` côté backend. Un override frontend précis vers `uuid@11.1.1`, suivi de tests d'export et du build navigateur, est la modification minimale. Si cette compatibilité échoue, il faudra isoler ExcelJS derrière une version corrigée/forkée plutôt que masquer l'avis.

## Architecture et conventions

- L'application est Vue 3/Vite et la logique métier doit rester dans les services/composables (`documentation/docs/architecture.md`, `documentation/docs/contrib/conventions.md`).
- Les tests Vue utilisent Vitest/jsdom et PrimeVue est stubé globalement (`documentation/docs/testing/overview.md`, `documentation/docs/testing/unit-tests.md`).
- Le champ riche appartient au domaine social transverse ; son contrat de sortie ne doit pas changer (`documentation/docs/domains/social-gamification.md`).
- `vite.config.js` crée actuellement des chunks manuels pour `xlsx`, `exceljs` et `quill`. Le chunk Quill devra être retiré avec la dépendance.

## Risques

1. **Exports cassés au runtime :** un build vert ne garantit pas la génération d'un classeur. Il faut tester au moins un export SheetJS et un export ExcelJS représentatifs.
2. **Contrat de l'éditeur :** Tiptap doit conserver la valeur HTML, la limite, les événements et le compteur attendus par les vues appelantes.
3. **Override transitive :** `uuid@11.1.1` doit être résolu réellement dans le lockfile et validé avec ExcelJS côté navigateur.
4. **Approvisionnement SheetJS :** la source officielle hors registre doit être épinglée, avec son intégrité enregistrée dans `package-lock.json`.

## Sécurité

- Aucun secret, jeton, droit, policy RLS ou contrôle d'accès n'est touché.
- Aucun audit ne sera ignoré ou abaissé.
- Aucun paquet vulnérable ne sera conservé au moyen d'une exception sans propriétaire et date d'échéance.
- La sortie HTML de l'éditeur conserve les protections de rendu existantes ; le ticket n'autorise pas à affaiblir la sanitation.

## Conclusion

Le ticket peut être traité sans migration métier des 26 parcours d'export : mise à niveau officielle de SheetJS, suppression de Quill au profit de Tiptap déjà présent, override contrôlé de UUID pour ExcelJS, puis tests de contrat et gates CI. C'est le chemin le plus petit qui satisfait les critères Jira tout en limitant les régressions.

## Résultat d'implémentation

- `xlsx@0.20.3` provient de la distribution officielle SheetJS épinglée dans le lockfile.
- `exceljs@4.4.0` résout désormais `uuid@11.1.1` grâce à un override ciblé.
- Quill est entièrement retiré. Les éditeurs Social, Mail et Tâches utilisent le composant Tiptap partagé `TextAreaComponent.vue`.
- `npm audit --omit=dev` retourne zéro vulnérabilité.
- 37 tests ciblés passent, ainsi que les 13 tests de sécurité backend.
- Les builds frontend, documentation et présentation passent. La commande agrégée locale a produit tous les artefacts mais son export PDF conserve un processus Vite enfant ouvert sous Windows ; le gate GitHub Actions Linux reste le verdict final de livraison.
